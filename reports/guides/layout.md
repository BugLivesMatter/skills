# Верстка отчетов

## Абзацы, заголовки и страницы

Настрой единый базовый стиль, а затем отдельные стили заголовков, подписей
и таблиц. Основной текст: TNR 14, по ширине, первая строка 1,25 см,
межстрочный 1,5, интервалы до/после 0 пт. Не имитируй отступ пробелами
и не создавай вертикальные интервалы пустыми абзацами. Не оставляй ручные
переносы строк из скопированного PDF: при выравнивании по ширине они
создают растянутые пробелы. Не растягивай последнюю строку абзаца.

Нумерованные заголовки разделов по умолчанию выравнивай слева с отступом
1,25 см; ненумерованные структурные заголовки — по центру. Используй
стили заголовков для навигации и содержания. В учебном профиле допустимы
интервалы 6–12 пт перед заголовком и 3–6 пт после, без пустых строк.
Не переноси слова в заголовках. Не выделяй полужирным целые обычные абзацы.

У заголовка включи связь со следующим абзацем и запрет висячих строк;
у обычного текста — контроль висячих строк, без связи всех абзацев в цепочку.
Обычный раздел не получает `pageBreakBefore`. Допустим разрыв после
отдельного титульного листа или там, где он прямо нужен по заданию.
Не вставляй разрыв, чтобы скрыть проблему с размером таблицы/рисунка.
Не заполняй страницу искусственным текстом ради объема.

Профиль с минимумом разрывов отличается от п. 6.2.1 ГОСТ 7.32-2017.
Если пользователь требует строгий режим, соблюдай начало структурных
элементов и разделов с новой страницы, а не обещай одновременно оба режима.

Для нумерации используй поле PAGE, а не введенные вручную числа.
На титуле скрой номер через особый колонтитул первой страницы;
на следующей странице номер продолжает общий счет. Если титула нет,
не скрывай номер первой страницы автоматически.

## Таблицы

- Таблица — редактируемый объект с шириной в пределах рабочей области
  страницы. Для книжного А4 при заданных полях рабочая ширина — 165 мм.
  Подбирай ширину столбцов по содержанию, а не поровну автоматически.
- Везде Times New Roman **14 пт**, включая заголовки, примечания в ячейках,
  вложенные таблицы и объединенные ячейки. Не уменьшай кегль, чтобы уместить
  широкую таблицу: сократи формулировки без потери смысла, перенеси слова,
  раздели таблицу по смыслу или используй обоснованный альбомный лист.
- Используй белый фон и тонкую черную сетку с наружными и внутренними
  границами, ориентировочно 0,5 пт. Не оставляй цветные полосы,
  невидимые белые границы, декоративные тени и диагональные разделители.
  Это профиль по образцам; ГОСТ допускает более простую внутреннюю сетку.
- Шапка — по центру, при необходимости полужирная. Текстовые значения —
  слева, числовые — единообразно по центру или по правому краю.
  Не применяй выравнивание по ширине к узким ячейкам: оно растягивает слова.
  Абзацный отступ в ячейках — 0, до/после — 0 пт, межстрочный — 1,0.
- Вертикальное выравнивание выбирай по содержанию: центр для коротких
  значений, верх для длинных пояснений. Высота строки — автоматическая
  или «не менее», а не жестко заданная: текст не должен обрезаться.
  Оставляй небольшие одинаковые внутренние поля ячеек, примерно 1–2 мм.
- Над таблицей слева без красной строки помести `Таблица 2 — Результаты
  сравнения моделей`, без точки в конце. Свяжи подпись с началом таблицы.
  Используй сквозную нумерацию; вариант по разделам — только последовательно
  для всего документа. Перед таблицей должна быть ссылка в тексте.
- Номер справа над таблицей и объединенная строка с названием внутри
  встречаются в личных образцах. Это альтернативный стиль кафедры,
  не профиль по умолчанию: воспроизводи его только по запросу/методичке.
- Повторяй шапку на следующей странице. Запрети разрыв обычной строки
  таблицы между страницами. Очень высокую строку сначала переработай,
  чтобы запрет разрыва не создавал пустые страницы или выход за поля.
- При переносе длинной таблицы для строгого оформления над следующей
  частью нужно `Продолжение таблицы 2`. Автоматический повтор шапки
  сам по себе эту надпись не создает. Если редактор не умеет ее размещать,
  раздели таблицу на явно оформленные части, сохрани номера/ширины столбцов
  и проверь переносы после окончательного экспорта.
- В шапке укажи единицы измерения. Выдерживай одинаковую точность чисел;
  пустые значения обозначай осмысленно и объясняй. Не округляй так, чтобы
  менялся вывод. После таблицы объясни наиболее существенное сравнение.

## Рисунки, схемы и графики

Каждый объект получает ссылку в основном тексте до размещения, само
изображение по центру и отдельную подпись **снизу**:

`Рисунок 3 — Граф-схема взаимосвязи фреймов в предметной области`

Подпись — TNR 14, по центру, без красной строки и точки в конце,
при нескольких строках интервал 1,0. Внутри одного отчета используй
одно тире-разделитель и единый способ нумерации. Номер не пропускай,
даже когда рисунок один. Не подменяй подпись заголовком внутри картинки.
Свяжи абзац с изображением со следующим абзацем подписи; сама подпись
не должна переноситься отдельно от изображения. Длинный блок уменьши
до читаемого размера или переработай; не создавай цепочку keep-with-next
на всю страницу. Предпочитай встроенное изображение без плавающего обтекания.

Размещай иллюстрацию сразу после первого упоминания или на ближайшей
следующей странице. После подписи/рядом в основном тексте дай пояснение:
что сравнивается, где виден результат и как он связан с задачей.
Для составного рисунка допускаются панели а), б) с общей содержательной
подписью, если каждая панель остается читаемой.

Графики строй программно по реальным данным (например, Matplotlib),
схемы — средствами построения диаграмм. Генерация картинок не подходит
для графиков с точными значениями. Храни код и данные воспроизведения,
если они входят в задачу. Не рисуй неподтвержденные измерения.

- Белый фон, спокойные контрастные цвета, тонкая ненавязчивая сетка.
- Подписанные оси и единицы, понятная легенда без перекрытия данных.
- Сопоставимые масштабы при сравнении; у столбцов обычно ноль по оси
  значений. Логарифмическую шкалу, обрезанную ось и интервалы неопределенности
  поясняй. Не используй 3D для обычного сравнения и декоративные эффекты.
- Различай серии также типом линии/маркера, чтобы график читался без цвета.
- Экспортируй вектор, если редактор его корректно поддерживает, иначе PNG
  примерно 300 dpi при окончательном размере. Проверяй размер надписей
  **после вставки**: большой исходный рисунок с маленьким шрифтом может
  стать нечитаемым. Внутренние оси/узлы подбирай по читаемости, обычно
  10–12 пт в итоговом размере; подпись под рисунком всегда TNR 14.
- Для граф-схем избегай пересекающихся подписей и слишком плотных узлов.
  Если вся схема не читается, покажи общий вид и отдельные фрагменты
  в основной части, не создавая самовольно приложение.

## Техническая памятка DOCX

Если доступен `python-docx`, задавай страницу через `Mm(210)`, `Mm(297)`,
поля через `Mm`, шрифт через `Pt(14)`, отступ через `Cm(1.25)`.
Проверь наличие реального Times New Roman у экспортера: подстановка
другого шрифта меняет переносы. Не выдавай замену за точное соответствие.

Ключевые значения WordprocessingML для проверки/создания:

| Элемент | Значение/действие |
| --- | --- |
| `w:rFonts` | `ascii`, `hAnsi`, `eastAsia`, `cs` = `Times New Roman`; исключить конфликтующие theme-атрибуты |
| `w:sz`, `w:szCs` | `28` (полупункты, то есть 14 пт) |
| Основной `w:jc` | `both` |
| `w:ind/@w:firstLine` | около `709` twips для 1,25 см |
| `w:spacing` | `before=0`, `after=0`, `line=360`, `lineRule=auto` для 1,5 |
| Ячейки/подписи | `firstLine=0`; строка `240`, `auto` для 1,0 |
| `w:tblBorders` | `top`, `left`, `bottom`, `right`, `insideH`, `insideV`: `single`, `sz=4`, `color=000000` |
| `w:tblHeader` | На строках шапки, чтобы повторять их при переносе |
| `w:cantSplit` | На обычных строках таблицы |
| `w:keepNext` | На заголовках, подписи таблицы и абзаце изображения |
| `w:pageBreakBefore` | Не включать у обычных учебных разделов |

Проверяй свойства на уровне runs, стилей символов, абзацев, таблиц,
цепочки `basedOn`, `docDefaults` и темы: `font.size is None` означает
наследование, а не автоматически 14 пт. Прямое форматирование может
перекрыть правильный стиль. Обходи также вложенные таблицы.
Отдельно оценивай технические таблицы титула: их невидимые границы
не являются дефектом содержательной таблицы.

После создания/редактирования экспортируй PDF доступным редактором
(например, Word или LibreOffice), затем преврати страницы в изображения
(Poppler `pdftoppm`, PDFium или другой доступный рендерер). Просмотри
каждую страницу. Проверяй подписи, таблицы, графики и переносы в финальном
экспорте, а не только XML и извлеченный текст. Не применяй массовую
перезапись свойств к чужому отчету без учета формул и структуры документа.
